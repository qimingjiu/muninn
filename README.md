# 雾尼 Muninn · 长程学情陪伴 Agent

> **参赛形态**：通用叙事记忆引擎（本体）× 长程学情陪伴（首发验证场景）
> 
> 赛道：GOAI 世界人工智能开源大赛 · 无界应用｜BoundlessAgents · AI+教育赛题
> 
> 自拟细分场景：**长程学情陪伴 Agent**

**雾尼 Muninn** 是通用叙事记忆引擎，以 **AI+教育 · 长程学情陪伴** 为首发验证场景参赛。

它要解决的不是「不忘记」，而是 AI 记忆的**碎片化原罪**：现有教育 Agent 能推题，却不记得学生三个月来卡在哪里、为什么卡、现在通了没有。人类记忆的本质不是存储而是**编织**——因材施教的前提，是有人记得你三个月来卡在哪里。

## 核心主张

- **现有系统记住「发生了什么」，雾尼持续修正「我如何理解你」**
- 记忆不该是一盒卡片，该是一部还在连载的书
- 核心认识论立场：**「我知道我对你的理解可能错，并且我能修正」**

---

## 三层叙事记忆引擎

```
┌─ 认识层（lifetime periods / 长程理解层）───────────┐
│  对人/关系/主题的活叙事文档                          │
│  增量重述 + 版本史 + 全套防漂移机制                  │
├─ 线索层（general events / 草蛇灰线系统）────────────┤
│  开放线索登记簿：未闭合状态的追踪                    │
│  ACTIVE / DORMANT / SILENT 三池                     │
│  merge / split / 反刍节律                           │
├─ 碎片层（specific episodes）───────────────────────┤
│  事件桶：VAD 情感坐标 + 情绪调制衰减                  │
└────────────────────────────────────────────────────┘
```

检索输出不是 top-k 卡片，而是「**叙事上下文包**」——相关碎片 + 所在线索位置 + 当前认识状态。

## 十分钟 Demo 脚本（教育场景）

| 时间 | 内容 | 设计意图 |
|---|---|---|---|
| 0:00-1:00 | 开场对比：「我终于把三个月前卡我的那章搞懂了」→ 普通教育 Agent vs 雾尼 | 十秒内立起差异：别人接话，我们闭环 |
| 1:00-3:00 | 历史压缩：导入三个月学习陪伴记录 → 37 事件 / 12 线索 / 5 核心学情认识 | 时间压缩法，解决认识层价值需数周显形的死穴 |
| 3:00-5:00 | 学情认识生成对比：不是「数学薄弱/学习认真」垃圾画像；是带证据、反证、边界条件的「卡点结构」论断 | 展示论断的证据结构，命中「学情诊断」验证项 |
| 5:00-7:00 | 人为反例：评委输入「最近我其实不想学这门了」→ 置信 0.82 → 0.57 | AI 当众承认「我不那么确定了」 |
| 7:00-9:00 | 伏笔回收：「终于把那个一直卡我的东西解决了」→ 草蛇灰线显影 | 完成叙事闭环，学情报告更新 |
| 9:00-10:00 | 收尾：现有教育 AI 解决「答对这道题」，我们解决「学生在时间中变化时，AI 如何修正自己对他的理解」 | 定位定格，扣回赛题题眼 |

## 任务闭环（对齐 Boundless Agents 核心作品要求）

1. **任务输入**：学生日常学习交互：自由对话、学习打卡、提问、情绪表达
2. **意图理解**：识别学习问题 / 状态变化 / 情绪事件；区分「新事实」与「旧线索的新证据」
3. **记忆编织**：碎片层登记事件（VAD 情感坐标）→ 线索层碰撞检测 → 认识层增量重述学情理解
4. **结果交付**：当下：携带叙事上下文的陪伴响应；周期：学情报告（线索状态变迁 + 认识演化 + 证据链 + 建议）
5. **验证与反馈**：过程评测三指标 + 学生对诠释层的最终解释权
6. **安全边界**：心理论断权限墙 + 危机协议 + 不替代教师评价声明

## 本地运行

```bash
npm install
npm run dev    # 默认 http://localhost:7100
```

可选：启用**实时 LLM 判定**（反例判定、伏笔回收、自由输入路由等由大模型实时推理；无 key 时自动回退到内置预计算脚本，全部功能仍可演示）：

```bash
# 在项目根目录新建 .env.local（已被 .gitignore 排除）
KIMI_API_KEY=sk-你的-Moonshot-API-Key
```

密钥只在 dev server 服务端读取，由 `/moonshot` 代理在转发时附加 Authorization 头，**不会注入客户端 bundle**。

```bash
npm run build   # 产物在 dist/
```

| 数据类型 | 来源 | 授权与处理 |
